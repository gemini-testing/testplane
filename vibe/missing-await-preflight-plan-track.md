## Decisions and remaining boundaries

1. One TypeScript AST/TypeChecker rather than Babel plus a second tree; cost: TypeScript becomes a runtime dependency.
2. Use a dedicated worktree from `origin/master`, not the current development branch. This supersedes the incorrect researched-HEAD base; dependencies must be installed from master's lockfile rather than copied from the old worktree.
3. Maintain the Russian plan's tracker/ledger manually rather than changing headings for English-only helper scripts; cost: bookkeeping is not automated by those scripts.
4. Run real API smoke in a subprocess against build and use the supported local Chrome backend; cost: this does not establish remote Grid compatibility. Browser execution is intentionally replaced only at the terminal API smoke boundary.
5. Use CHANGELOG.md (Releases.md is a release schedule) and in-memory syntax fixtures plus temporary integration files; no runtime behavior cost.
6. Keep the documented bounds for unknown consumers, mutable/relational flow, complex closures/recursion, any/missing/dynamic types, external helper bodies, DSL wrappers/referenced callbacks/hook-only/injected/dynamic/transpiled code, and race/any input completion. Cost: static false negatives remain possible; successful preflight is not a safety proof.
7. Preserve INIT/beforeAll/discovery/worker/dev-server ordering; cost: preflight does not prevent initialization/discovery side effects.
8. Treat supplied execution logs as the verification evidence, not an independent reviewer rerun; compare screenshots with base, and make no production-scale tsconfig performance claim. Cost: remote Grid and worst-case large-project performance require separate environment-specific validation.
